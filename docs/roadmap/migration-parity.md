# Migration parity: roadmap tooling onto the tech-tree skill

Before: `github/main` 1498b472 (own `tools/roadmap/build.py`, `check.py`, `history_gap.py`). After: the vendored design-skills `tech-tree` skill (ea48dcf9) driven by `docs/roadmap/tech-tree.yaml`. Both were built on 2026-11-20 from the same 412 nodes. This file is a migration record; delete it after the merge if it is no longer wanted.

**Result: no information is lost.** Every field of every node that a page showed before is shown after, in the same place or an additional one. 6 069 (node, field) pairs were compared; 0 are lost, 2 771 differ in where they appear, and every difference is an addition or a rename of a region (full list: `migration-parity.csv`, one row per node and field, with the page and region or table column before and after).

## How it was measured
`migration-parity.csv` locates each non-empty field of each node in the pages: a track-page table column (`Node table:<column>`, `Details per node:<column>`), the folded list (`Folded items`), a region of `roadmap.md` (`main:<region>`) or the timeline. Table cells are matched by node id and column; free text is matched as a normalised substring of the region. `overview` and `diagram` show by where the node is drawn, so they are not compared as text; the Mermaid code of every page was compared with the class lines removed: the trees (nodes, shapes, labels, edges) are byte-identical on all 13 pages, only the legend differs. The class lines (they carry each node's rating and state colour) were compared per node: all 450 node-to-class assignments are equal, with `userdec` read as `gate` or `decided` (5 decided owner calls) and `defect` as `finding` (33). `kind`, `state`, `outcome`, `depends_on` and `track` are compared in their table column.

## History gap tool
The skill's `history_gap.py` replaces `tools/roadmap/history_gap.py` (the command is kept as a wrapper). Measured on the same 1 408 commits before 2026-11-01:

| | old script | skill script |
|---|---|---|
| strong matches (sha or branch/tag): node / folded / none | 464 / 923 / 9 (+12 `dropped`) | 464 / 923 / 21 |
| all matches, weak included: node / folded / none | 675 / 713 / 8 (+12 `dropped`) | 675 / 713 / 20 |

Per commit, the two agree on all 1 408 commits except the 12 that matched only the `dropped` list; they now read "none". Equal numbers needed one config entry: `history.merge_subject` (a regex for the merge subjects of this repo: `merge: NAME - ...`, `merge NAME sha: ...`, `Merge feat/x: ...`) and a `status` weak ref that skips "paper §N", as the old script did. Without them 354 commits fell to "none".

Differences, both kept as listed losses, none on the pages:
- **`dropped` bucket**: gone (the list is now `dropped.md`, which the tool does not read). Upstream change 1 in the report would restore it.
- **ADR-file table** (ADR numbers 1-83 with no file in `docs/adr` and what git history says about them): not in the skill's script. `history_audit.py` (kept) already lists ADRs no node cites; the table is not reproduced.
- The summary's heading "Nodes not on the main page" now also counts nodes with no start date (60). The default `--before` (2026-11-01) is not baked into the wrapper: pass `--before 2026-11-01` for the old window.
